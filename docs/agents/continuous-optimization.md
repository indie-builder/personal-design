# 持续架构与 AX 优化

开始日期：2026-10-18。首轮基线：`e6f0412`。使用 `codebase-design` 的 module、interface、seam、implementation、adapter 术语评估改动；每轮必须交付可验证结果，不能以文件数量或调用次数代表改善。

## 目标与停止条件

减少完成常见修改所需阅读的职责数量、重复知识和资源生命周期细节；保留现有产品行为、可访问性、媒体语义与数据所有权。维护文本继续遵守 20,000 bytes 上限，生成／外部来源沿用现有豁免规则。

按实际证据选择高价值改动，先识别调用方、失败方式与验证入口，再实现、验证、自审和记录后续。没有证据支持的抽象不新增。候选全部处理或证明不值得修改时，关闭本轮改进目标；遇到授权范围外的操作则仅暂停该路径。Agent 延迟和实际 token 消耗未经测量，不宣称量化提升。

代码优化已获用户授权；真实内容同步、生产写入、外部发布不能由这项授权推导。现有每日内容同步授权门保持独立。LoopX 的本地状态不入库。

## 第一轮：动效浏览器 module

`run-all.mjs` 保留套件次序、失败汇总、浏览器复用和最终释放；新增 `motion-browser.mjs` 的 `openMotionBrowser(chromium, origin)`，返回 `{ tab, cdp, viewport, close }`。module 隐藏浏览器初始化、失败清理、定位器链、参数映射和 CDP 超时；检查脚本继续使用原有注入 interface。

依赖是 Playwright 外部浏览器。通过传入 `chromium` 在同一 interface 下使用真实 adapter 与本地失败夹具；未为单个实现引入额外 port 或框架。旧初始化失败时清理与最终 `finally` 释放的顺序保持一致。原有注释随实现迁移。

实现前覆盖的失败方式：页面创建失败、首次导航失败、CDP 创建失败、定位器 timeout 参数不兼容、CDP 异常与超时、错误页面或 session 被绑定。既有运行器测试继续验证 origin 注入、顺序和缺失检查失败；完整生产验收验证浏览器复用与实际检查调用。

## 第二项：聊天恢复规则

将 `use-saved-chat.ts` 中的恢复规则移到 `@personal-design/ai-chat` 的 `normalizeSavedChat(initial)` interface，内置列表复用包内 `builtinAgents`。包维护最新内置资料、顺序和头像策略；hook 只维护 schema 读取、hydration 后载入、存储错误、节流写入及页面生命周期。原始输入不变，会话与摘要保留；未改变存储键、schema 或故障降级。

实现前增加缺失／过期资料、无效头像、自定义顺序、摘要保留和重复恢复稳定性验证。`node --test packages/ai-chat/src/index.test.mjs apps/web/lib/chat-persistence.test.mjs apps/web/lib/chat-stream.test.mjs` 的 16 项通过；包与 Web 类型通过。整合后 `pnpm test` 为 224 项，lint、格式、导航、技能库存与快照漂移检查全部通过；重新生产构建和完整 `pnpm check:chat` 通过（chat-api、chat-analytics、查询进度浏览器）。
