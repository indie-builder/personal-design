# OpenUI 移动端通用组件契约

本契约属于 [DESIGN.md](../../../DESIGN.md) 的 AI 问答局部适配，说明任意业务如何使用同一组件库；不另立视觉标准，也不以某组生成结果决定组件能力。当前官方 schema 允许的组件均可按语义使用；内容型回答可以没有 Form 或 Button。默认业务案例、推荐规则和演示数据不属于通用渲染层。

## 三层职责与执行位置

| 层级 | 负责什么 | 执行位置 |
| --- | --- | --- |
| Renderer 强约束 | 共享尺寸／主题、单列内容、原生选择与日期、编辑状态、按钮布局和强调层级；不改业务数据、动作顺序或 payload | [外壳尺寸](../../../apps/web/components/ai-chat.module.css)、[回答样式](../../../apps/web/components/ai-chat-ui.module.css)、[主题映射](../../../apps/web/lib/ai-chat-ui-theme.ts)、[移动组件库](../../../apps/web/components/ai-chat-mobile-library.tsx)、[Renderer与回传](../../../apps/web/components/ai-chat-ui.tsx) |
| Generation 建议 | 按任务选择组件、合理分组、短操作文案、说明口径、保留长内容与空状态；建议数量不成为数据截断条件 | [提示词生成器](../../../apps/web/scripts/generate-openui-prompt.mjs)，由官方库生成 schema 与运行提示词 |
| Business agent | 领域知识、用户任务、业务字段、推荐逻辑、真实或标注的示例数据；决定是否需要某个流程 | [默认智能体](../../../packages/ai-chat/src/index.ts)及用户自定义系统提示词 |

生成提示词不能替代浏览器约束；渲染器不能因某个示例偏好删除 schema 能力。业务智能体不能覆盖共享控件规则，也不能让通用层默认执行选方案、安排试点等领域动作。`Save Changes` 的通用回传为“请根据我更新的内容继续”，并以结构化上下文附带官方事件的表单状态。

## 表单提交消息

遵循 [OpenUI交互模型](https://www.openui.com/docs/openui-lang/interactivity)，将 `humanFriendlyMessage` 与 `formState` 分开处理。用户气泡仅呈现简短操作描述；提交内容放入默认折叠的只读详情，允许随时展开查看。不得把所有字段平铺到气泡正文，也不显示原始JSON。

保留官方事件的状态结构与值类型，存入消息metadata；当前请求、重新生成、后续历史及摘要输入统一通过content/context信封传给模型。提交快照不随表单之后的变化而修改，刷新可恢复。未修改且未注册到SDK状态的默认值以原生成回答为上下文，不由宿主猜测补齐。

## 基础 token 与语义角色

规范值由 DESIGN.md 定义，源码以 `--chat-*` 为尺寸来源，回答及官方 body portal 的 `--answer-*` 继承；组件不根据生成内容自行发明字号或圆角。

| 角色 | 当前项目映射 |
| --- | --- |
| 正文／输入值／占位／选择文本 | 13 CSS px，实际值与提示同号，聚焦前后不跳变 |
| 字段标签／辅助说明／校验／表头 | 12 CSS px；代码12px等宽，不继承比例正文 |
| 标题／指标／图标 | 15／18／14 CSS px；指标数字不能代替标题角色 |
| 字段／动作 | 20px行盒、至少44px操作目标、10px圆角；输入8px 12px内边距，动作10px 12px |
| 结构间距 | 内容组12px、Form默认16px、标签与字段6px、动作组8px |
| 主题与状态 | 全站中性双主题；图表系列使用统一低饱和palette，焦点、错误、禁用和选中由各自语义表达 |

这些尺寸是本项目在窄幅聊天里的选择。Apple的pt、Android的dp和Web的CSS px不能混作同一种单位。保留浏览器缩放；不为统一字号设置禁止缩放的viewport。

## 七类组件契约

| 类别 | 通用契约与边界 |
| --- | --- |
| 1. 布局与内容容器 | Stack／Card单列，Card为无外框内容组；文字、列表、代码可以独立构成完整回答。Tabs表示平级视图，Accordion收纳可选细节，Steps只表达真实有序步骤。不得强迫每个回答进入表单、业务阶段或卡片仪表盘。 |
| 2. 状态、长内容与空数据 | 长标签、说明、数值和代码保持可读，允许换行或组件内部滚动；不得裁掉必要信息。无数据与数值0区分；空、部分生成、校验失败、渲染失败和禁用要有明确语义。建议分组不等于删除字段、记录或强迫分步。 |
| 3. 输入与选择 | text／email／password／number／url／textarea、日期、已选及空select、滑块值、编辑条目、composer、创建表单及portal输入均使用同一输入角色。标签始终可见；Select／DatePicker使用原生控件。TextArea最小80px，长内容可增加高度。EditableTable逐项展开并保留全部列、当前状态、确认和撤销；不要求双击、右键或悬停。 |
| 4. 动作 | 只在有真实下一步时显示。单项满宽；内容容器宽于320px时两个短操作等宽并排；窄容器或三个及以上操作纵向满宽。每组最多一个primary，重复或破坏性primary降为secondary；顺序及payload不变。编辑确认填充、撤销描边。导航、发送、复制等工具保持图标型及可访问名称，不机械铺满。 |
| 5. 表格、指标与图表 | Table优先突出2–4个核心维度是生成建议；更多列须保留，按组或表格内部横滑阅读，不让整个页面横向滚动。表格数据13px、表头12px。图表按趋势、比较、分布等数据关系选择，给出标题、单位、口径与可见结论；不得只为展示组件而造图或编造数据。通常2–3系列／少量Tabs是阅读建议，不是截断规则。Line／Area／竖向Bar默认240px绘图区；其他官方adapter及图表按实际实现核对，不声称每个图表都透传同一height。圆图无额外220px上限。 |
| 6. 媒体 | Image／Gallery／媒体卡片保留来源内容与替代说明；不虚构图片URL，不用装饰图片强迫所有回答卡片化。图片加载失败、缺失、极端比例和多项媒体需分别检查；现有图片库能力不等于已实现任意视频协议。媒体或代码操作不能仅在hover可见。用户询问代码时使用CodeBlock。 |
| 7. Overlay与浮层 | Modal仅用于必要的短暂聚焦任务，普通内容留在回答内。body portal、画廊与图表tooltip继承相同主题和角色；保留可见焦点、关闭入口及适用的Escape／焦点返回行为，长内容在浮层内可滚动。关闭态引用不等于打开态已验收。 |

## 消息交互状态

只有列表最后一条assistant消息在请求结束后可编辑。最新消息是user、等待回答、正在生成或发生失败时，所有此前回答继续只读；该状态由聊天宿主计算，模型不能覆盖。

| 历史回答中的功能 | 行为 |
| --- | --- |
| 输入、选择、日期、滑块、勾选、开关、编辑表格字段 | 锁定，保留已填写值 |
| 生成Button／IconButton、列表／卡片的生成动作 | 锁定或转为静态展示，不发起后续请求 |
| 表格分页、横向滚动、Tabs、Accordion、编辑条目展开 | 继续可用，仅改变本地查看状态 |
| 图片预览、复制内容 | 继续可用 |

`GeneratedAnswer`传入独立只读上下文；移动库只对编辑组件设置禁用边界，动作回调和历史表单回写再作阻断。Table等查看组件的内部按钮不按DOM标签一刀切禁用，历史消息也不使用假streaming状态，避免隐藏原有数值或改变显示。

## 官方依据与项目判断

[Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)建议以样式区分同组按钮的强调程度，避免用不同尺寸制造优先级。[Material Button](https://developer.android.com/develop/ui/compose/components/button)用filled／outlined／text表达高、中、低强调。[WCAG 2.1 SC 2.5.5](https://www.w3.org/WAI/WCAG21/Understanding/target-size)的44×44 CSS px属于AAA级目标尺寸要求，并有例外；不是所有等级的统一硬门槛。

本项目据此区分动作层级、保留可点击面积；13px文字、10px圆角、320px容器阈值、每组最多一个primary及何时满宽，是手机聊天场景适配，不宣称由官方规范逐项强制规定。

## 通用状态验收矩阵

以下是任意业务的回归契约，不以默认案例通过替代通用能力验证。当前已有覆盖见 [一致性审查](../execution/ai-chat-consistency-audit.md)与 [执行记录](../execution/ai-chat.md)；本轮通用压力结果见 [ai-chat-contract/result.json](../execution/evidence/ai-chat-contract/result.json)，仅更新已执行范围，其余明确记为“未跑”。

| 场景 | 必须观察的结果 | 当前证据边界 |
| --- | --- | --- |
| registry与组合样例 | 全部schema定义可引用，parser无错误／未解析引用 | 既有82定义、10组目录覆盖；不是82独立交互E2E |
| 纯内容／代码／无动作回答 | 不强加Form、推荐或下一步；代码可读可复制 | 已回放不含业务名的纯内容、CodeBlock及Accordion组合；未强加表单／动作 |
| 长中英文、超长字段、更多列／记录 | 换行或局部滚动，必要数据不丢，页面不横溢出 | 已测长中英文、超长无断词内容、长数值和六列表场景，无页面或回答容器横溢出；长列表及逐项数据完整性压力断言未跑 |
| 空数组、缺失值、0、单点／多系列 | 区分无数据与0；选图不歪曲数据，说明可读 | 已测Table／LineChart／ImageGallery空数组；缺失值、0、单点及更多系列边界未跑 |
| 输入空／有值／聚焦／错误／禁用 | 值与占位13px；标签12px；校验和状态可识别 | 既有18个输入三视口覆盖；本轮已测长选项、禁用OptionCard与必填校验提示 |
| 1／2／3+动作与破坏性动作 | 按容器宽度排列，最多一个primary，动作内容及顺序保留 | 已测1／2／5项、重复primary及破坏性primary：每组primary≤1、破坏性primary为0；另有1／2／3项的容器排列证据。降级动作真实点击后mock请求保留原Action文本的断言已通过 |
| 编辑、撤销、提交、刷新 | 原数据与编辑状态可追溯，不套用领域动作 | 移动编辑回归已重跑；任意字段组合及通用Save Changes措辞的定向验证未跑 |
| 部分流、失败、中止、重试 | 不丢已知状态，不以静态成功截图代替错误路径 | 既有API定向测试；本轮混合组件流状态未跑 |
| 媒体与打开态overlay | 缺图／长内容可理解，主题、关闭、焦点与目标范围正确 | 既有画廊、明暗Modal及Escape证据，本轮补空ImageGallery；媒体加载失败及全部浮层组合未跑 |
| 尺寸、主题和输入方式 | 至少320／390及桌面窄框，明暗、键盘、触摸；原生缩放可用 | 本轮5组压力数据已测320浅色／390深色／1440浅色，无页面／回答容器横溢出或结构错误提示；iOS真机键盘未跑 |

压力回放命令与边界见 [执行记录](../execution/ai-chat.md#通用组件压力回放)。动作排列的独立产物为 [ai-chat-button-layout/result.json](../execution/evidence/ai-chat-button-layout/result.json)：280px内容容器纵向，350／438px容器的两个操作等宽并排；单项满行、三项纵向。上述结果均为固定样例浏览器验收，不代表任意模型输出或所有schema参数组合。

82项registry包含Col、Series、Point等数据定义，Slice等声明也可能不挂载；组件名称出现在fixture仅证明引用覆盖。需将源码审查、parser覆盖、DOM几何检查、实际交互和真实模型输出分开记录，不能合并成“全部82项独立E2E通过”。
