# Generated answer visual redesign

Mode: Operate / Read. Code-led redesign of the generated answer layer using the same compact semantic scale as the established, user-pinned mobile chat shell.

THESIS: A clear mobile reading surface, with hierarchy carried by typography, alignment and restrained dividers. Use concise choice rows and a full-width mobile action area whose buttons share the field geometry.

BOUNDARY: The user's latest clarification is visual only. Keep the OpenUI schemas, Pi backend, case facts, existing fields and flow, neutral identity, male avatar assets, Menu/Plus shapes and external project navigation. The latest visual pass reduces the shell and answers together; avatar32px, all shell headings15px, messages/lists13px and composer padding6px 8px 6px 12px. Do not add a wizard, delete fields, collapse optional questions, or change business steps as part of this task. The earlier answer preferring fewer questions does not override this clarification.

VISUAL CONTRACT: Neutral project colors and Albert Sans; body13px, labels12px, captions12px, answer heading15px, metrics18px, actual input values and placeholders13px; labels and supporting hints12px. General Card is an unboxed content group. Radio and checkbox choices are whole-row targets separated by hairlines with a neutral selected surface; OptionCard retains its own visible keyboard focus. Inputs have a subtle filled background,10px corner and one focus ring. Answer, official-portal and editable confirm/reset action groups fill the available width with8px gaps. A single action spans the row. Two short actions share equal columns only when the content container is wider than320px; at320px or narrower, or with three or more actions, every action is full-width in a vertical stack. Each group has at most one primary: duplicate or destructive primary variants become secondary without changing order or payload. Editable confirm is filled primary and reset is outlined default. Text buttons fill their column, use the same10px radius as fields,13px text/20px line box,10px 12px padding and44px minimum height. Do not use trailing small pills or transparent borders that shrink the visible button. Shell navigation/send/copy icon shapes and global button rules stay unchanged. Read-only tables keep a single quiet10px-radius boundary and internal horizontal scrolling; editable entries use unboxed dividers with the existing expand/reset/submit behavior. Metrics are compact label/value rows, not a stack of dashboard cards. Every chart type uses the centrally mapped light/dark slate, sage and sand palette and retains readable labels. Icons are14px neutral lines with no decorative badge backgrounds. Mobile geometry is the same inside the desktop480px frame.

VERIFICATION: Compare the same case at320/390px and in the desktop/user817px viewport, with light/dark. Preserve selection, native pickers, editable-row state/reset/submit, graph tabs and generated follow-ups. Keep screenshots of the answer form, editing, and data review. Finish with an independent visual review and scoped documentation.

SYSTEM: ai-chat.module.css `.page --chat-*` is the shared shell/answer size-token source; ai-chat-ui.module.css `answer-*` tokens inherit those values, including explicit scopes for official body portals and chart tooltips; ai-chat-ui-theme.ts maps every official OpenUI typography role to that scale and owns shared colors, radii, spacing and chart palettes. Answer group spacing12px. Shared control minimum44px; input values13px via `--chat-input-size:var(--chat-body-size)`; OpenUI and creation-field line boxes use20px with8px 12px padding and44px minimum height; generated textareas start at80px and grow with content; browser-native zoom stays available; same-role components cannot opt into independent sizing.

SUPPORTING COPY: All actual values, input/textarea placeholders and empty/selected select text use13px across text/email/password/number/url/textarea, dates, slider values, editable rows, composer, creation forms and portals. Focus never changes their size. Field labels, hints, validation messages, option subtitles, inline-header/list/switch/callout descriptions, metric ancillary text and secondary/tertiary text retain caption12px. Do not add a viewport zoom restriction.

CATALOG CONSISTENCY: Code uses12px SFMono-Regular/Menlo/monospace on a neutral surface with an always-visible copy button. Switch keeps a44×44px hit target around a28×18px visible track. Disabled accent, emphasized borders, highlight and sunk states map to project tokens. The82 registered definitions are source/fixture coverage, not82 independently exercised interactive components; see docs/design/execution/ai-chat-consistency-audit.md for runtime coverage.

CONTROL PROPORTIONS: Tabs/Accordion/Chips control text13px; table data13px and headers12px with8px 12px cell padding. Radio/checkbox vertical padding6px; OptionCard padding10px with natural content height; switch-row vertical padding2px. Preserve group12px, Form gap16px, the established240px chart setting and uncapped circular charts; this does not reinstate the rejected density pass.

BUTTON RATIONALE: Equal sizing with visual emphasis follows Apple and Material hierarchy guidance;13 CSS px text,44 CSS px targets and the320px/count layout rule are this project’s choices. Apple pt, Android dp and WCAG CSS px are distinct units. Full width applies to answer actions, not all tools. Sources and scope are recorded in docs/design/execution/ai-chat.md.

GENERALITY: This surface applies to every schema-allowed component and any business domain. Renderer constraints, generation guidance and business-agent knowledge have separate responsibilities; see docs/design/controls/openui-mobile.md. Content-only answers need no Form or Button. Field/column/series counts are readability suggestions, never permission to drop necessary data or force a workflow. The default case is agent content, not a universal component template.
